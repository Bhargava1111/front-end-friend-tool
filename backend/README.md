# Django REST Backend + PostgreSQL

API backend for Sri Mahalakshmi Stores. Deploy **database and backend together** on Render using the included Blueprint.

## One-click deploy (Render — DB + API combined)

The file `render.yaml` creates **both** resources in one step:

| Resource | Name | What it does |
|----------|------|----------------|
| PostgreSQL | `mnxstore-db` | Production database |
| Web service | `mnxstore-api` | Django API (auto-linked to DB) |

### Steps

1. Open [Render Dashboard](https://dashboard.render.com/)
2. Click **New** → **Blueprint**
3. Connect GitHub repo: `https://github.com/Bhargava1111/pulagantigowthami143`
4. Render shows a preview:
   - `mnxstore-db` (PostgreSQL)
   - `mnxstore-api` (Web Service)
5. Click **Apply** — Render creates the database, links `DATABASE_URL`, builds and deploys the API

No need to create PostgreSQL and Web Service separately.

### After deploy

- **Health check:** `https://mnxstore-api.onrender.com/api/v1/health/`
- **API base:** `https://mnxstore-api.onrender.com/api/v1`
- Demo data is seeded on first start (`ALLOW_DEMO_SEED=1` in `render.yaml`)

**Demo login:** `admin@mnxstore.in` / `Demo@12345`

### Frontend `.env`

```
API_URL=https://mnxstore-api.onrender.com/api/v1
VITE_API_URL=https://mnxstore-api.onrender.com/api/v1
```

---

## If you already created a Web Service manually

Delete the old **Web Service** (without linked DB) and deploy again using **Blueprint** above. Manual web-only deploys fail without `DATABASE_URL`.

## Local development

```bash
docker compose up -d
pip install -r requirements.txt
cp .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver 8000
```

API: `http://localhost:8000/api/v1`

## Environment variables

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | Auto-set by Render Blueprint from `mnxstore-db` |
| `DJANGO_SECRET_KEY` | Auto-generated by Render Blueprint |
| `CORS_ALLOWED_ORIGINS` | Frontend URLs allowed to call the API |
| `DEBUG` | `False` in production |

See `.env.example` (local) and `.env.production.example` (manual deploy).
